# Green Field

### Development Plan

1. First use Kim to investigate the surrounding codebase.
    - If Kim has any questions about the codebase let him ask me.
2. Have him come up with a clear implementation plan.
    - If more than one implementation plan is possible, have him give me a few concise options and let me choose which one to implement.
3. Have Ritsuko create new files and implement the code.
4. Have Kim analyze that changes and make sure they fit with the plan. If they do not, have him suggest changes to the implementation.
5. Once Kim agrees with the changes. Have Ritsuko check for any refactoring to make the code DRY and clean.
6. Only check that the new code passes linting and typing checks.

If you find that the linting and typing keep failing, you should stop the implementation and ask for help. I will be able to help implementations go smoothly.

### Primary means of making updates
Do not update existing files, simply create new ones.

### Secondary means of making updates
When an existing file needs to be changed. Add the changes but as comments in the new file. This way we can easily track the changes and revert if necessary.
